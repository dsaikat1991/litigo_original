# Changelog

All notable changes to this project are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **Appointments** — a new entity for client conferences, meetings with co-counsel, or anything time-bound that isn't a court hearing (which already has its own Hearings tab). New migrations `0022_appointments.sql` (table: `advocate_id`, optional `case_id` — same case-optional pattern as `notes`, since a meeting can happen before a case exists — `title`, `appointment_date`, optional `appointment_time`/`location`/`notes`, `is_done`/`completed_at` synced by trigger, same pattern as `tasks`) and `0023_reminder_email_log_appointment_kind.sql` (widens the reminder dedupe log's `item_kind` check constraint to accept `'appointment'`, same as when `'limitation'` was added). New `lib/data/appointments.ts` with the full CRUD + list surface, mirroring `lib/data/tasks.ts`/`lib/data/notes.ts`.
  - **Case detail page**: new "Appointments" tab (`components/cases/add-appointment-form.tsx` + `components/cases/appointment-item.tsx`), same shape as the Tasks tab — a checkbox to mark done, Edit/Delete, and an overdue indicator once a not-done appointment's date has passed.
  - **New standalone `/appointments` page** (`app/appointments/page.tsx`, added to the nav bar between Calendar and Notes) — same case-optional pattern as `/notes`: a "Case (optional)" `Select` on both the add form and each appointment's edit mode, using the same `"__none__"` sentinel and `cases` prop convention just built for notes.
  - **Reminders pipeline**: `ReminderItem["kind"]` gained `"appointment"`; `buildReminders()` takes a 4th `appointments` argument. `ReminderItem.caseId` is now optional (`caseId?: string`) to support a standalone appointment with no case — `ReminderRow` falls back to linking `/appointments` instead of `/cases/undefined` when absent, and only shows the case-name subtitle line when a case is actually linked. Wired into all four existing consumers: the dashboard's "Upcoming" digest, the notification bell, `/notifications`, and the `send-reminders` email cron (`lib/email-templates/reminder-digest.ts` updated with an "Appointment" label and a `titleOf()` helper that only appends " — case title" when a case is actually linked).
  - **Calendar**: `MonthCalendar` now accepts an `appointments` prop and renders them as distinct blue chips (hearings stay gray), each showing its time if set; `/calendar`'s heading updated to "Upcoming hearings & appointments".
  - **Today page**: a new "Today's appointments" section above the cause list, shown whenever there's at least one appointment dated today; the "nothing listed" empty state now only shows when both the cause list and today's appointments are empty.
  - **Search**: appointments are now searchable (title + location) in both the navbar's quick search (`quickSearch`) and the full `/search` page (`searchAll`), following the exact column/date-range-filtering pattern already used for hearings/tasks/documents. `QuickSearchResult["type"]` gained `"appointment"`.
  - **Needs setup**: run `0022_appointments.sql` then `0023_reminder_email_log_appointment_kind.sql` in the Supabase SQL editor, in that order — every page/route that now queries the `appointments` table (dashboard, notifications, notification bell, `/today`, `/calendar`, `/search`, the case detail page, `/appointments` itself, and the reminder-email cron) will error until the table exists; the email cron additionally needs `0023` before it can log a sent appointment reminder without hitting the `item_kind` check constraint.

### Fixed

### Added
- **Notes, learnings, and updates can now be linked to a case from the standalone `/notes` page.** Previously the only way to attach a note to a case was to add it from that case's own Notes tab (where the link is implicit); the standalone page always saved `case_id: null`. `AddNoteForm` (`components/cases/add-note-form.tsx`) now accepts an optional `cases` prop and renders a "Case (optional)" `Select` — using the same `"__none__"` sentinel pattern as the other optional case-link pickers — but only when `caseId` isn't already supplied (so the case-tab's own Add Note form, which already knows its case, is unchanged). `NoteItem`'s edit mode got the same picker (also gated on a `cases` prop), so an existing note's case link can be added, changed, or cleared after the fact — this required removing `case_id` from `NoteUpdateInput`'s Omit list in `lib/data/notes.ts`, since it was previously locked at creation time. `app/notes/page.tsx` fetches `listCases()` once and passes it down to both.

### Changed
- **Removed the `focus:border-gray-900` utility from every text input, textarea, and custom form-control trigger app-wide** (56 occurrences across 21 files — every case/hearing/task/note/research form, auth forms, profile, settings, search). On focus this turned the border a near-black solid color, which combined with the existing `focus:ring-2 focus:ring-gray-900/10` halo rendered as a stark black rectangle around the field — flagged as an unwanted "black outline" on every focused input. Focus is now indicated by the ring alone (border stays its normal `border-gray-300`), which is subtler and consistent with the newer shadcn-style components (`Select`, `Checkbox`, `DateField`) that never had the border-darkening treatment to begin with. Mechanical sed replacement, verified via `grep -r "focus:border-gray-900"` returning zero matches afterward.

### Fixed
- Dashboard "Your cases" table: the "Next date" cell (an ISO date + a days-away badge in a flex row) had no `whitespace-nowrap`, so in the narrower table layout after the Stage column was added, the date string itself would line-wrap at its hyphens (`2026-09-` / `19`) instead of the row simply widening. Fixed by adding `whitespace-nowrap` to the cell. While in there, also switched the displayed format from ISO (`YYYY-MM-DD`) to `DD-MM-YYYY` (new `formatDateDDMMYYYY()` in `lib/dates.ts`, pure string slicing — no `Date` object, so no timezone risk), applied to both the desktop table and the mobile card view of the same list. Scoped to just this list for now; other pages still show raw ISO dates.

### Changed
- **"Your cases" table on the dashboard**: dropped the Client column and added a Stage column in its place (Case, Court, Next date, Stage, Status). "Stage" is new — there was no case-level field for it, so it's pulled from the `stage` field of whichever hearing was most recently logged for that case. New migration `0021_case_current_stage.sql` adds `cases.current_stage` and extends the existing `sync_case_next_hearing_date` trigger (renamed `sync_case_hearing_fields`, since it now syncs two fields instead of one) to also copy `hearings.stage` onto it on every hearing insert/update — same denormalization already used for `next_hearing_date`, so the dashboard list doesn't need a join per case. `current_stage` is excluded from `NewCaseInput`/`CaseUpdateInput` in `lib/data/cases.ts`, same as `next_hearing_date`, since it's trigger-managed, not user-editable. **Needs setup**: run `0021_case_current_stage.sql` in the Supabase SQL editor — the dashboard's case list queries will error until the column exists, since `current_stage` is now part of the shared `CASE_LIST_COLUMNS` select.

### Fixed
- Dashboard stat tiles fine-tuned for consistency with the overdue-hearing changes: **"Critical deadlines open"** previously only counted critical *tasks* (`listOpenCriticalTasks`), so it showed 0 even while a case with an unresolved critical limitation date was visibly flagged right below it — now adds a count of non-disposed cases with a `limitation_date` set (`(cases ?? []).filter(c => c.limitation_date !== null).length`), reusing the `cases` list already fetched for "Your cases" rather than a new query. **"Hearings this week"** previously counted the raw `listCasesWithHearingWithin(7)` result, which still includes overdue hearings even though those now live exclusively in the dashboard's "Overdue — not yet updated" section — now filters to `daysAway(next_hearing_date) >= 0` so the two sections don't double-count the same hearing.

### Added
- **Codebase-wide shadcn-style pass**, replacing every remaining native `<select>`, `<input type="checkbox">`, and `<input type="date">` with the custom Radix-based components, so no page is left mixing styled and browser-default form chrome:
  - **Select** (`components/ui/select.tsx`, already built for the case-link picker) now also used for: Case type (New/Edit case forms), Status (Edit case form), Application heard (Add/Edit hearing), Note type (Add/Edit note), Research source type (Add/Edit research), Related hearing (Upload document). Each "— None —"-style optional field uses a local `"__none__"` sentinel, same pattern as the original case-link picker, since Radix `Select.Item` can't take an empty-string value.
  - **New `components/ui/checkbox.tsx`** (Radix `Checkbox`, styled black/gray to match the app instead of the browser's default blue accent) used for: the tags filters on `/search` and the filters dialog, the in-app/email reminder-threshold toggles in Settings, task done/critical toggles (`task-item.tsx`, `hearing-tasks.tsx`, `add-task-form.tsx`), and the read-only task-done indicator in the case timeline. Confirmed Radix `Checkbox` renders an internal hidden native input when placed inside a `<form>` (its `isFormControl` bubble-input mechanism), so the `/search` page's plain native GET-form checkboxes keep working unchanged — verified live by submitting with a tag checked and confirming `?tags=...` lands in the URL.
  - **`DateField`** (moved from `components/search/date-field.tsx` to `components/shared/date-field.tsx`, since it's no longer search-specific) now also used for: Filing date and Limitation date (New/Edit case forms), Hearing date and Next date fixed (Add/Edit hearing), Due date (Add/Edit task). Added a `clearable` prop (default `true`) and a small "Clear" / "Today" footer inside the calendar popover, matching what the native date input's own picker offered — required fields (e.g. "Hearing date *") pass `clearable={false}` to hide "Clear" entirely. Since swapping away from the native `<input type="date" required>` also drops the browser's built-in required-field validation, `add-hearing-form.tsx`'s `handleSubmit` gained an explicit `if (!hearingDate)` guard to replace it (the edit-mode equivalent in `hearing-item.tsx` didn't need one, since it's always initialized from an existing non-null DB value and its date field isn't clearable).
  - Every swap was done keeping each form's existing sizing convention (compact `py-1.5` forms vs. the case forms' `py-2`, and `w-auto`/no-width selects that were sized to their content) via a `className` override on the trigger, so nothing changed visually beyond replacing the native chrome.

### Changed
- Restyled `ReminderRow` (`components/reminders/reminder-row.tsx`, shared by the dashboard's "Upcoming" list, `/notifications`, and the notification bell dropdown) from an individually-boxed card (`rounded-md border bg-white p-3`) to a flat row with a bottom divider (`border-b border-gray-100 last:border-b-0`) — the per-item box looked cluttered stacked several in a row, especially in the compact bell dropdown. The three list containers now wrap the rows in one shared card (dashboard/`/notifications`: `rounded-md border border-gray-200 bg-white`; bell dropdown: `-mx-3` to bleed edge-to-edge within `DropdownMenuContent`'s own padding) so the divider reads as one connected list instead of loose rows.

### Added

### Fixed
- Case detail tab bar (now 6 tabs after adding Documents) was wider than a phone screen with no wrap or scroll handling, which forced the entire page to zoom out to fit it on mobile — shrinking all text app-wide, not just the tabs. Wrapped the tab list in its own horizontally-scrollable container instead.
- The nav bar's user menu (avatar + "Hi, {name}") went blank for a moment on every page navigation and refresh — it's a client component that re-fetches the profile from scratch on each mount, and since `NavBar` is rendered independently per page (no shared layout), that's every navigation. Now caches the last-known avatar/name in `sessionStorage` and hydrates from it synchronously (`useLayoutEffect`, before paint) while it quietly re-fetches in the background; cache is cleared on logout.
- Switching to a tab with taller content (e.g. Hearings, after Phase 2 added more fields) could trigger a vertical scrollbar that shifted the whole page horizontally. Added `scrollbar-gutter: stable` on `html` so the scrollbar's width is always reserved, whether or not it's actually showing.
- The signup trigger only ever inserted a bare `profiles` row, never copying the name a user actually provided — not our own signup form's `full_name`, and not what Google supplies (`name`/`picture`) via OAuth. Fixed now that Google login is live, since a Google user would reasonably expect their name/photo to already be there (`0008_profile_metadata_on_signup.sql`). Only affects new signups — existing profiles are untouched.
- shadcn's init step renamed the expected font CSS variable from `--font-geist-sans` to `--font-sans` in `globals.css`, but didn't update `layout.tsx`'s `next/font` config to match — would have silently broken the font again (same class of bug as the earlier Arial fallback issue) had it not been caught before committing.
- The nav bar's user menu (avatar/name) didn't update after editing the profile or uploading a photo without a full page reload — it's a client component that fetches its own data once on mount, so `router.refresh()` (which only re-renders server components) didn't reach it. - Reverted the earlier "nudge the bell icon up 2px" fix — that was based on a hand-traced estimate of the SVG path that missed how far the dome's arc actually bulges. Confirmed via the rendered page too: the icon's on-screen bounding box now centers exactly on the same line as the avatar circle next to it (0px difference).
