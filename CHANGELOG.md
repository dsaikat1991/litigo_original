- **Billing (Razorpay) shipped — free tier + Pro subscription**: Free plan caps active (non-disposed) cases at 5; Litigo Pro (₹299/month or ₹2,999/year) removes the cap. New `subscriptions` table (`0017_subscriptions_and_case_limit.sql`) tracks plan/billing cycle/status per advocate, RLS-readable by its owner only (writes only via the server, using the service-role key). The actual limit is enforced by a Postgres trigger on `cases` (`enforce_case_limit()`) — not just a client-side check — since case creation goes straight from the browser to Supabase with no server checkpoint otherwise; `app/cases/new` also shows a proactive "upgrade" banner and disables the form before a blocked submission would even happen. Accounts created before 2026-09-18 are grandfathered with no limit (kept in sync in both the trigger and `lib/billing.ts`).
  - New `/pricing` page (was a "free during early development" placeholder) with real Free/Pro plan cards and working upgrade buttons.

  - `app/api/webhooks/razorpay` is the actual source of truth for "is this advocate on Pro" — verifies Razorpay's webhook signature, then flips a subscription to `active` (on `subscription.activated`/`charged`) or `cancelled` (on `subscription.cancelled`/`completed`/`halted`). The client-side checkout success callback only means the modal closed, not that payment was confirmed, so it never itself grants access.

### Fixed
- Case detail tab bar (now 6 tabs after adding Documents) was wider than a phone screen with no wrap or scroll handling, which forced the entire page to zoom out to fit it on mobile — shrinking all text app-wide, not just the tabs. Wrapped the tab list in its own horizontally-scrollable container instead.
- The nav bar's user menu (avatar + "Hi, {name}") went blank for a moment on every page navigation and refresh — it's a client component that re-fetches the profile from scratch on each mount, and since `NavBar` is rendered independently per page (no shared layout), that's every navigation. Now caches the last-known avatar/name in `sessionStorage` and hydrates from it synchronously (`useLayoutEffect`, before paint) while it quietly re-fetches in the background; cache is cleared on logout.
- Switching to a tab with taller content (e.g. Hearings, after Phase 2 added more fields) could trigger a vertical scrollbar that shifted the whole page horizontally. Added `scrollbar-gutter: stable` on `html` so the scrollbar's width is always reserved, whether or not it's actually showing.
- The signup trigger only ever inserted a bare `profiles` row, never copying the name a user actually provided — not our own signup form's `full_name`, and not what Google supplies (`name`/`picture`) via OAuth. Fixed now that Google login is live, since a Google user would reasonably expect their name/photo to already be there (`0008_profile_metadata_on_signup.sql`). Only affects new signups — existing profiles are untouched.
- shadcn's init step renamed the expected font CSS variable from `--font-geist-sans` to `--font-sans` in `globals.css`, but didn't update `layout.tsx`'s `next/font` config to match — would have silently broken the font again (same class of bug as the earlier Arial fallback issue) had it not been caught before committing.
- The nav bar's user menu (avatar/name) didn't update after editing the profile or uploading a photo without a full page reload — it's a client component that fetches its own data once on mount, so `router.refresh()` (which only re-renders server components) didn't reach it. Added a small `profile-events` pub/sub so `ProfileForm` and `AvatarUploader` can tell the user menu to refetch immediately after a successful save.
- Reverted the earlier "nudge the bell icon up 2px" fix — that was based on a hand-traced estimate of the SVG path that missed how far the dome's arc actually bulges. Measuring the real path with `getBBox()` shows the glyph is symmetric (2.0 units of margin on both top and bottom of its 24-unit box), and the previous nudge was actively making it worse. Confirmed via the rendered page too: the icon's on-screen bounding box now centers exactly on the same line as the avatar circle next to it (0px difference).
- Date-vs-"today" comparisons (task overdue check, the new dashboard reminders) used `Date.toISOString()`, which converts to UTC — for any timezone ahead of UTC (e.g. IST) during its early morning hours, this silently rolled "today" back a day, throwing off overdue/day-count calculations. Replaced with a local-calendar-date helper (`lib/dates.ts`).
- `cases.next_hearing_date` was left stale when the hearing that set it was deleted (the sync trigger only ran on insert/update). Migration `0002_hearing_delete_sync.sql` adds an `AFTER DELETE` trigger that recomputes it from the remaining hearings.
- The Geist font loaded via `next/font` was never actually applied — `globals.css` hardcoded `font-family: Arial` on `body`, overriding it. Also removed an incomplete `prefers-color-scheme: dark` block that didn't match the rest of the UI (all components use explicit light colors), which would have rendered a broken half-dark page.
